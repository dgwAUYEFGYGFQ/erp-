## 1. 整体建设目标

采购云成本管理模块当前已具备基础成本核算能力，可通过核算属性、物料属性基础价、核算模板和核算单，结合 SAP 物料主数据、PLM 物料属性及公式逻辑，计算物料价格。现阶段系统已完成“按规则算价”的基础闭环，但仍存在属性和规则大量人工维护、预测价缺少独立台账、正式价与预测价场景边界不清、历史价格查询困难、预实复盘不足、品类权限缺失、预测价未与订单测算平台和目标绩效管理打通等问题。

本次建设目标是以采购云成本模块为基础，建设面向采购业务的成本管理与价格预测平台，实现物料成本价格的规则化计算、台账化沉淀、趋势化分析、预测化管理和业务协同输出。总体建设目标如下：

1. 建立统一核算属性和属性值标准化能力，减少 PLM、SAP、OA 与采购云字段不一致导致的维护和取价风险。
2. 区分正式价与预测价两类业务场景，正式价支撑 OA 调价审批闭环，预测价支撑未来月份物料基础价格预测。
3. 将基础价维护升级为价格因子规则库，按品类、价格类型、有效期、版本和优先级管理正式价规则与预测价规则。
4. 建设正式价台账和预测价台账，统一沉淀物料价格、来源单据、月份、版本、状态和同步结果。
5. 支持预测价版本管理、价格走势图、预实对比、价差分析、方向性判断准确率和目标绩效分析。
6. 将预测价同步至订单测算平台，支撑 MTO 业务模式下的订单成本测算。
7. 建立品类维度权限体系，按用户授权品类控制核算、规则、台账、看板和导出范围。
8. 明确采购云与 PLM、SAP、OA、订单测算平台之间的系统边界和数据流向，为后续 PRD 细化与系统建设提供统一蓝图。

### 2.3 存在问题&痛点

- 当前问题：核算属性、属性值和基础价规则需要大量人工维护，且需与 PLM / SAP 字段及属性值完全一致，维护成本高、出错风险高。
- 当前问题：正式价规则与预测价规则缺少清晰隔离，基础价规则偏静态，无法支撑按月滚动预测和多版本管理。
- 当前问题：预测价缺少独立台账，历史预测结果只能从核算单逐张查看，同一物料同一被预测月份的多个预测版本难以对比。
- 当前问题：正式价和预测价缺少统一价格台账，业务无法便捷查看物料历史价格走势、价格波动和来源单据。
- 当前问题：预测价与正式价之间缺少预实对比、偏差金额、偏差率、方向性判断准确率和预测版本复盘能力。
- 当前问题：成本模块缺少按品类控制的数据权限，难以满足成本数据敏感性管理要求。
- 当前问题：预测价尚未同步订单测算平台，也未沉淀为品类采购目标价格，无法支撑订单成本测算和目标绩效管理。
- 改造目标：在现有核算能力基础上，建设覆盖正式价核算、预测价管理、价格台账、预实分析、订单测算对接、目标绩效和品类权限控制的一体化成本管理能力。
- 业务价值：减少线下 Excel 测算和人工汇总，提高价格计算准确性和可追溯性，支撑采购价格走势分析、预测复盘、订单测算和管理层目标管控。

## 3. 系统蓝图&数据流程图（概要设计 blueprint）

### 3.1 系统流程图

> 业务流程图：[business-flow.drawio](business-flow.drawio)（双击用 Draw.io 打开编辑）

目标系统主流程围绕“规则准备 - 核算执行 - 台账沉淀 - 协同输出 - 分析复盘”展开。正式价与预测价共享属性、价格因子、模板和计算追溯底座，但在规则、流程、台账字段、外部协同和分析口径上保持隔离：

- 正式价：采购云正式价核算单计算正式调价价格，核算单在采购云审批通过后同步正式价台账，并同步 OA 调价单；OA 承担调价审批，审批状态回传采购云；OA 审批通过后由 OA 按现有机制同步 SAP 价格库，采购云不负责 OA 到 SAP 的同步。
- 预测价：采购云预测价核算单计算未来月份物料基础价格，不关联供应商，不触发 OA，不同步 SAP；核算单在采购云审批通过后同步预测价台账，再由预测价台账同步订单测算平台，用于预实对比、价格走势、目标绩效和预测准确率分析。
